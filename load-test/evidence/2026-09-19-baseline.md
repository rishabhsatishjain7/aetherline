# Load-test baseline — 2026-09-19

This is the documented baseline going forward. Per the methodology note in
`CLAUDE.md`, the exact command, duration and host-load snapshot are recorded
here so future runs can be compared honestly.

## Exact command

```powershell
cd load-test
.\.venv\Scripts\Activate.ps1
locust -f locustfile.py --host http://localhost:8000 --headless -u 20 -r 2 -t 3m --csv=final_baseline
```

- Flags: `-u 20 -r 2 -t 3m` (20 users, spawn rate 2/s, 3 minutes)
- Run window: 2026-09-19 13:18:00 → 13:21:07 (187 s)
- Locust 2.31.5, host venv (`load-test/.venv`), Python 3.14.2

desktop throughout. Absolute latency percentiles from this box are therefore
**not transferable to other hardware** — treat them as a same-host comparison
point.

## How to use this

Compare a future run **only** against these numbers, and **only** if it used
the same `-u 20 -r 2 -t 3m` flags and a broadly similar host-load state.
Never compare total request counts across runs — total requests depend on how
fast the server responded, not just on duration.
